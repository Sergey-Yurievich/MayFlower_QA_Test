# Тест-кейсы и чек-лист

Части 1 и 2 задания: все проверки для двух эндпоинтов и их приоритизация.

- `POST /user/create` — регистрация, `multipart/form-data`: `username`, `email`, `password`
- `GET /user/get` — список зарегистрированных пользователей

## Схема приоритизации

| Prio | Критерий | Что делаем |
|---|---|---|
| **P0** | Основной флоу не работает или утечка данных. Без этого продукт нельзя отдавать | Автоматизируем, гоняем на каждый коммит |
| **P1** | Валидация, уникальность, контракт ответа, устойчивость к отказам. | Автоматизируем |
| **P2** | Границы, форматы, семантика HTTP, нормализация. Создаёт мусор в данных и усложняет отладку | Автоматизируем выборочно |
| **P3** | Тексты, косметика, масштабируемость на горизонте. Заметно, но терпимо | автоматизация по остаточному принципу |

Приоритет определяет состав прогонов: 
P0 входит и в смоук (тег `Smoke`), и в регресс (тег `Regress`), 
P1–P3 — только в регресс. 

---
P0 - Critical
P1 - Major 
P2 - Normal 
P3 - Minor \ Trivial

## 3. Тест-кейсы

### ТК 1.01

**Эндпоинт /user/create. Пользователь с валидными данными регистрируется**

Приоритет: **P0** 

#### ПУ
- Подобраны незанятые `username` и `email`

#### Шаги
1. Отправить `POST http://18.194.45.232:3333/user/create`, тело `multipart/form-data`:
   - `username`: незанятое значение из ПУ, например `smoke`
   - `email`: незанятый адрес из ПУ, например `smoke@example.test`
   - `password`: `Passw0rd!2026`
2. Посмотреть код ответа и тело

#### ОР
- Код ответа `200`
- `success` равно `true`
- `details.id` — положительное число: пользователю присвоен `id`
- `details.username` совпадает с отправленным

### ТК 1.02

**Эндпоинт /user/create. Ответ на регистрацию содержит id, переданные username и email, created_at и updated_at**

Приоритет: **P0**

#### ПУ

- Подобраны незанятые `username` и `email`

#### Шаги
1. Отправить `POST http://18.194.45.232:3333/user/create`, тело `multipart/form-data`:
   - `username`: незанятое значение из ПУ, например `fields`
   - `email`: незанятый адрес из ПУ, например `fields@example.test`
   - `password`: `Passw0rd!2026`
2. Посмотреть блок `details` в ответе

#### ОР
- Код ответа `200`
- `details.id` — положительное число
- `details.username` и `details.email` совпадают с отправленными
- `details.created_at` и `details.updated_at` заполнены

### ТК 2.03

**Эндпоинт /user/get. Зарегистрированный пользователь находится по username**

Приоритет: **P0**

#### ПУ
- Зарегистрирован пользователь, из ответа на регистрацию известны его `id`,
  `username` и `email`

#### Шаги
1. Отправить `GET http://18.194.45.232:3333/user/get?username=<username из ПУ>`
2. Посмотреть записи в ответе

#### ОР
- Код ответа `200`
- В ответе ровно одна запись
- `id`, `username` и `email` записи совпадают с данными пользователя из ПУ

### ТК 2.04

**Эндпоинт /user/get. Список соответствует корректной схеме без поля password**

Приоритет: **P0**

#### ПУ
- Зарегистрирован пользователь, его `username` известен

#### Шаги
1. Отправить `GET http://18.194.45.232:3333/user/get?username=<username из ПУ>`
2. Посмотреть структуру ответа и поля записи

#### ОР
- Код ответа `200`, тело — JSON-массив
- У записи ровно пять полей: `id`, `username`, `email`, `created_at`, `updated_at`
- `id` — положительное целое число, остальные поля — непустые строки
- Поля `password` нет
